# 설치 가이드

README 의 빠른 설치로 부족할 때 보는 문서다. 설치 절차 자체는 패키지 안의 설치기가 에이전트에게
시키므로, 여기서는 **사람이 준비하고 판단해야 하는 것**만 다룬다.

## 1. 준비물

- **워크스페이스로 쓸 폴더 한 곳.** 새 폴더여도 되고 이미 문서가 있는 폴더여도 된다.
  - 여러 PC 에서 같이 쓰려면 구글 드라이브 동기화 폴더(데스크톱용 Google Drive)
  - 이 PC 에서만 쓸 것이면 일반 로컬 디렉토리
- **폴더에 파일을 쓸 수 있는 에이전트 도구.** 아래 2절의 도구 중 하나. 파일을 첨부만 하는
  대화형 채팅으로는 설치할 수 없다.
- **설치 패키지.** [Releases](https://github.com/proofer-tech/context-protocol/releases) 의
  `context-protocol-<버전>.zip`. 같은 버전에 빌드 번호(`-b2`, `-b3`)가 붙은 파일이 있으면 번호가
  가장 큰 것을 쓴다. 번호가 낮은 빌드에는 나중에 고친 결함이 남아 있다.

받은 zip 이 손상되지 않았는지 보려면 압축을 푼 뒤 `MANIFEST.md` 의 파일별 해시와 비교한다.

## 2. 도구별 설치

어느 도구든 마지막 말은 같다. **"이 파일을 압축해제해서 설치해줘"**. 다른 점은 폴더를 여는
방법과 설치 뒤 붙여넣기 단계뿐이다.

### Claude Cowork

1. 프로젝트를 만들고 워크스페이스 폴더를 연결한다.
2. zip 을 대화에 첨부하고 설치를 요청한다.
3. 설치기가 마지막에 출력하는 지침 블록을 **프로젝트 설정 > 지침**에 붙여넣는다. 서버에
   저장되는 값이라 에이전트가 대신할 수 없다. 이걸 빼먹으면 다음 세션부터 워크스페이스를
   자동으로 읽지 않는다.

Cowork 로 연결한 폴더에서는 삭제, 이름 바꾸기, git 같은 잠금 파일 도구가 막힌다. 로컬 디렉토리를
연결해도 같다. 프로토콜이 이를 알고 있으므로 에이전트가 우회해서 작업한다.

### Claude Code

1. 워크스페이스 폴더에서 `claude` 를 실행한다.
2. zip 을 폴더에 넣거나 경로를 알려 주고 설치를 요청한다. 에이전트가 쓰기 전에 대상 경로를 확인한다.
3. 붙여넣을 것이 없다. 다음부터는 `CLAUDE.md` 포털이 `CONTEXT.md` 를 자동으로 끌어온다.

### Codex (CLI, ChatGPT Work 모드)

1. CLI 는 워크스페이스 폴더에서 `codex` 를 실행한다. ChatGPT 는 Work 모드에서 그 폴더를 지정한다.
2. zip 을 건네고 설치를 요청한다.
3. 붙여넣을 것이 없다. `AGENTS.md` 포털을 스스로 읽는다.

### Cursor, Google Antigravity, Grok Build

워크스페이스 폴더를 열고(또는 그 폴더에서 CLI 를 실행하고) zip 을 건넨다. 셋 다 `AGENTS.md` 포털을
스스로 읽으므로 붙여넣을 것이 없다. Grok Build 는 대화형에서만 포털을 자동으로 읽고, `-p`
헤드리스 실행에서는 읽지 않는다.

### 그 밖의 도구

폴더에 파일을 쓸 수 있으면 `generic` 폴백으로 설치된다. 에이전트가 미검증 도구라는 사실을 한 번
알린다. 동작이 이상하면 이슈로 알려 주면 프로파일을 만든다.

## 3. 백엔드 질문에 답하기

설치 초반에 에이전트가 "이 폴더가 어떤 저장 위치인가" 를 묻는다. 폴더 경로로 추론한 값을 추천으로
보여 주지만, **고르는 것은 사람이다.** 고른 값은 `CONTEXT.md` frontmatter 에
`ws_backend_source: user` 로 기록되고 이후 어떤 세션도 덮어쓰지 않는다.

| 이런 폴더라면 | 고를 값 |
|---|---|
| 데스크톱용 Google Drive 의 `내 드라이브` 나 `공유 드라이브` 아래 | `gdrive` |
| 동기화되지 않는 일반 폴더 | `local` |
| OneDrive, Dropbox 아래 | `onedrive`, `dropbox` (프로파일 없이 폴백 규칙으로 동작) |
| 동기화 폴더 밖에 clone 한 git 저장소이고, 에이전트가 커밋하고 push 하길 원함 | `git` |

`git` 은 추천값으로 나오지 않는다. 폴더에 `.git` 이 있어도 마찬가지다. 코드 저장소에 설치했는데 에이전트가
커밋하길 원하지 않으면 `local` 을 고른다. `git` 을 고르면 반영 모드를 이어서 묻는다. 혼자 쓰면 수시반영
(`direct`), 조직의 공식 정본이면 승인반영(`review`, 에이전트는 PR 까지만)을 권한다. 폴더별로 다르게 둘 수도 있다.

나중에 바꾸려면 `CONTEXT.md` frontmatter 의 `ws_backend` 를 고치고 `ws_backend_source: user` 로
둔다.

## 4. 이미 설치된 워크스페이스 버전 올리기

새 버전 zip 을 같은 방법으로 건네고 "설치해줘" 라고 하면 된다. 에이전트가 루트의 `CONTEXT.md`
(또는 이전 버전의 흔적)를 보고 기존 설치로 판별해 `CONTEXT_MIGRATE.md` 를 돌린다. 지금 버전을
판별해 그 사이의 차이만 적용하며, 쌓아 둔 규칙과 기록을 덮어쓰지 않는다.

지금 버전은 `_context-protocol/CONTEXT_GUIDE.md` 안의 `Guide version:` 줄에서 확인한다.

에이전트가 기존 워크스페이스에 신규 설치(SETUP)를 시작하려 하면 멈추게 한다. 그 폴더의 기록이
사라진다.

## 5. 설치 후 확인

에이전트는 무엇이 생겼는지, 어느 백엔드로 잡혔는지, 붙여넣기가 남았는지만 보고하고 끝낸다.
다음에 할 일을 제안하지 않는 것은 의도된 동작이다.

직접 확인하고 싶다면 최소한 이것만 본다. 전체 목록은 패키지 `README.md` 의 "설치 후 확인" 절에 있다.

- 루트에 `CONTEXT.md`, `AGENTS.md`, `CLAUDE.md`, `_project.md`, `memory/MEMORY.md`,
  `action-log/`, `_context-protocol/` 가 있다
- `AGENTS.md` 와 `CLAUDE.md` 에는 규칙이 없고 `CONTEXT.md` 를 가리키기만 한다
- `CONTEXT.md` frontmatter 의 `ws_backend` 가 3절에서 고른 값과 같다
- `_context-protocol/CONTEXT_GUIDE.md` 의 `Guide version:` 이 설치한 버전과 같다
- `_context-protocol/tools/hwp2md.py` 가 있다

새 세션을 열고 "이 워크스페이스가 뭐야?" 라고 물어 `CONTEXT.md` 와 `memory/MEMORY.md` 를 읽고
답하면 연결이 된 것이다.

## 6. 자주 막히는 곳

**다음 세션에서 워크스페이스를 안 읽는다.**
Cowork 라면 붙여넣기 단계를 빠뜨렸을 가능성이 크다. 다른 도구라면 하위 폴더에서 시작하지 않았는지
본다. 세션은 워크스페이스 루트에서 시작한다.

**분명히 있는 파일을 에이전트가 "없다" 고 한다.** (`gdrive`)
아직 내려받지 않은 클라우드 파일은 샌드박스 셸에 보이지 않는다. 프로토콜은 호스트 측 도구로 다시
확인하게 되어 있다. 계속 그러면 해당 파일을 Drive 에서 "오프라인 사용 가능" 으로 두거나 한 번 열어
내려받게 한다.

**모든 도구가 `Resource deadlock avoided` 로 실패한다.** (macOS, `gdrive`)
파일이 없는 것이 아니라, 에이전트를 백그라운드 데몬으로 띄워 클라우드 파일을 내려받을 권한이 없는
상태다. 진단과 대응은 `_context-protocol/backends/gdrive.md` 의 "데몬 프로세스의 dataless 거부" 절.

**Cowork 에서 파일 삭제나 git 이 실패한다.**
정상이다. 연결된 폴더의 제약이다. 클라우드 동기화 폴더 안에 git 저장소를 두지 않는다는 규칙은
어느 도구로 열든 남는다.

**한글(hwp, hwpx) 문서를 못 읽는다.**
`_context-protocol/tools/hwp2md.py` 가 있는지 본다. 가이드 4.10절이 이 도구를 부른다.

## 7. 프리셋 적용

프로토콜을 설치한 뒤, 프리셋 이름을 대며 요청한다.

```
team-ops 프리셋으로 세팅해줘
```

에이전트는 프로토콜 버전을 먼저 맞추고, 프리셋의 폴더와 템플릿을 깐 뒤, 초기 문답(intake)으로 첫
객체를 채운다. 기존 파일을 옮겨야 하면 파일별 이동 계획을 보여 주고 승인을 받은 뒤에만 옮긴다.
프리셋 목록은 README 의 [프리셋](../README.md#프리셋) 절.

## 8. 제거

프로토콜은 폴더 안의 평범한 마크다운 파일이다. 루트의 `CONTEXT.md`, `AGENTS.md`, `CLAUDE.md`,
`_project.md` 와 `_context-protocol/` 을 지우면 된다. `memory/` 와 `action-log/` 와 주제별 폴더는
사용자의 기록이므로 필요하면 남긴다. Cowork 라면 프로젝트 지침에 붙여넣은 블록도 지운다.
