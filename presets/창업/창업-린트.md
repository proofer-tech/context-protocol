# 무결성 점검과 조회 레시피

Dataview 와 `.base` 를 쓰지 않으므로 검증과 집계를 파일 스캔으로 한다.

점검 대상 주의: 여기 적힌 명령은 **프리셋을 적용한 대상 워크스페이스**에서 돌린다.
프리셋 폴더(`presets/창업/`)는 설계 문서와 플레이스홀더만 있는 템플릿이라 훑으면
오탐이 난다. 위키링크 스윕과 Obsidian 잔재 검사에서 제외한다.

실행 위치 주의: 대상 워크스페이스가 Drive 마운트면 샌드박스 셸에서 안 보이는
cloud-only 파일이 있다. 빈 grep 결과는 아무것도 증명하지 못한다(GUIDE §3 하드 룰).
하네스의 호스트 파일 도구(Cowork 에서는 Desktop Commander 의 `start_search`)로 찾거나 먼저 그 도구로
읽어 하이드레이트한 뒤 셸을 쓴다. 이 워크스페이스는 hwp 와 pdf 원본이 대부분이라 지연이 특히 길다.

## 혼자 쓰는 워크스페이스라 아무도 지적하지 않는다

[[team-ops]] 는 여러 사람이 써서 lint 결과가 5분 뒤에 틀릴 수 있는 것이 문제였다.
여기는 반대 조건이고, 그것이 더 나쁜 문제를 만든다.

**여러 사람이 쓰는 폴더에서는 틀린 노트를 남이 발견한다.** 근거 없이 올라간
`validated`, 반증된 가설 위에 서 있는 제품, 출처가 사라진 시장 규모 숫자는 다음
사람이 읽는 순간 걸린다. 1인 워크스페이스에는 그 자리가 없다. 본인이 적은 문장은
본인에게 늘 그럴듯해 보이고, 반년 전에 올려둔 `validated` 는 다시 읽을 때도
`validated` 로 읽힌다. **lint 가 이 워크스페이스의 유일한 외부 눈이다.**

그래서 규율 검사 16 과 17 을 자동 검사보다 **더 자주** 돌린다. team-ops 가 그것을 분기에
한 번으로 둔 것은 사람이 상시 감시자로 붙어 있는 조건에서 나온 주기다. 검사 결과는
파일에 박아두지 않는다. 고쳐진 항목이 위반으로 남고, 혼자 쓰는 폴더에서는 그 스테일을
지적할 사람이 없어 목록이 통째로 무시된다.

## 점검 목록

코어 규칙 1~6 은 프로토콜 lint 가 본다. 여기서는 프리셋이 더한 7~18 을 본다. 규칙
본문은 [[창업-스키마]] 에, 프로퍼티 표는 [[창업-객체타입]] 에 있다.

| # | 점검 | 종류 | 방법 |
|---|---|---|---|
| 7 | `type:` 이 허용 값인가 | 구조 | `objects/` 전체에서 `^type:` 수집 -> 10개 값(concept + document + 8타입)만 나와야 한다 |
| 8 | 필수 프로퍼티와 `ownedBy` 존재 | 구조 | 타입별 PK 와 O 표시 필드를 루프로 대조. 사업체 를 뺀 7종은 `ownedBy` 존재도 본다 |
| 9 | 위키링크 해소 | 구조 | 모든 `[[...]]` 를 수집해 동명 md 파일이 실재하는지 대조 |
| 10 | 술어 어휘 준수 | 구조 | `links:` 하위 키를 수집해 창업-스키마 표와 대조 |
| 11 | 정/역 중복 | 구조 | 비정본 술어 8쌍을 스윕하고 상대 노트와 대조 |
| 12 | 객체에 broader 없음, ownedBy 대상이 사업체 | 구조 | `broader:` 존재 검사 + `links.ownedBy` 값이 `objects/사업체/` 의 노트인지 대조 |
| 13 | 가설 에 `falsifiable` | 구조 | 프로퍼티 또는 대응 본문 섹션이 비면 위반 |
| 14 | validated 에 근거 | 구조 | **역방향 스캔.** 근거 쪽 `supports` 를 모아 validated 목록에서 뺀다 |
| 15 | 근거 에 `collectedAt` 과 `sampleSize` | 구조 | 두 필드 존재 검사 |
| 16 | 숫자에 출처 | 규율 | 정량 표현 후보를 뽑고 그 파일 `sources` 가 비었는지 본다. 사람이 판정 |
| 17 | 반증된 가설 위에 산 것 | 규율 | invalidated 목록 -> `assumes` 백링크 -> 활성 상태인 것 |
| 18 | `submittedTo` 면 `submittedAt` 과 `version` | 구조 | 세 필드 조합 대조 |
| 추가 | 날짜 폴더 없음 | 구조 | `action-log/` 하위에 디렉토리가 없어야 한다 |
| 추가 | Obsidian 잔재 없음 | 구조 | `.base` 파일, dataview 블록이 없어야 한다 |

타입 폴더명은 `사업체 제공물 고객군 가설 근거 마일스톤 자금 제출문서` 여덟이다
([[창업-레이아웃]]). **이 이름을 임의로 바꾸면 그 타입의 검사가 조용히 건너뛰어진다.**
`근거` 를 `증거` 로 고치는 식의 동의어 교체가 특히 위험하다. 규칙 14 와 15 가 통째로
침묵하고 에러는 안 난다.

## 구조 검사 명령 (하이드레이트 후 셸)

```sh
# 7. type 값 분포. concept, document, 8개 타입명만 나와야 한다.
#    objects/ 아래에서 document 가 나오는 자리는 동명 서브폴더 안의 부속 노트뿐이다
#    (서브폴더 규칙은 창업-레이아웃). 그 밖에 document 가 나오면 타입 배정이 빠진 것이다
grep -rh '^type:' objects/ | sort | uniq -c

# 8. 타입별 필수 프로퍼티. 창업-객체타입 의 O 표시를 그대로 옮긴 것이다.
#    서술 필드를 본문 섹션으로 쓰는 워크스페이스면 대응 헤딩으로 바꿔 검사한다.
#    Owned 구현 7종은 ownedBy 존재도 함께 본다. 값이 사업체 인지는 12-b 가 본다
for d in 사업체 제공물 고객군 가설 근거 마일스톤 자금 제출문서; do
  case "$d" in
    사업체)   c=사업체;    req="slug name oneLiner stage problem" ;;
    제공물)  c=제공물;   req="slug title kind status valueProp" ;;
    고객군)   c=고객군;    req="slug title who jobToBeDone" ;;
    가설) c=가설; req="slug title about status statedAt falsifiable" ;;
    근거)   c=근거;   req="slug title kind collectedAt sampleSize finding" ;;
    마일스톤) c=마일스톤;  req="slug title status definitionOfDone" ;;
    자금)   c=자금;    req="slug title kind status provider" ;;
    제출문서)  c=제출문서;   req="slug title kind version status" ;;
  esac
  for f in objects/$d/*.md objects/$d/*/*.md; do
    [ -f "$f" ] || continue
    case "$f" in */$c.md) continue;; esac
    for k in $req; do
      grep -qE "^$k: *[^ ]" "$f" || echo "missing $k: $f"
    done
    [ "$d" = 사업체 ] && continue
    grep -qE '^  ownedBy: *[^ ]' "$f" || echo "missing ownedBy: $f"
  done
done

# 9. 위키링크 대상 목록 (좌변)
grep -rhoE '\[\[[^]|#]+' objects/ object-sets/ object-views/ datasources/ \
  | sed 's/\[\[//' | sort -u
# 9. 실재 노트 인덱스 (우변). comm -23 로 빼면 좌변에 남은 것이 dangling 이다
find . -name '*.md' -not -path './_*' -exec basename {} .md \; | sort -u

# 10. 사용된 술어 (links: 블록의 2단 들여쓰기 키)
grep -rhoE '^  [a-zA-Z]+:' objects/ | sort | uniq -c
#    어휘 전체(창업-스키마): claims claimedIn supports refutes supportedBy refutedBy
#    tests testedBy assumes cites ownedBy offers pursues holds targets servedBy
#    describes aboutSegment supersedes supersededBy fundedBy funds requires delivers
#    sourceFile relatedObjects relatedViews references
#    여기 없는 키는 규칙 10 위반이다. 상위 인덱스를 가리키려고 자금: 이나
#    제출문서: 같은 타입명 키를 만든 경우가 가장 흔하다

# 11-a. 비정본 술어 전수 스윕. 템플릿은 정본 슬롯만 주므로 여기 걸리는 것은
#       전부 손으로 적힌 것이고, 상대 노트에 같은 사실이 있으면 위반이다
grep -rnE '^  (claimedIn|supportedBy|refutedBy|testedBy|offers|pursues|holds|servedBy|funds|supersededBy):' objects/

# 11-b. 실제 중복인지 상대 노트와 대조. 아래는 지지 쌍의 형태이고
#       나머지 쌍은 네 변수만 바꿔 같은 모양으로 돌린다.
#       블록 경계를 지키는 awk 를 쓴다. grep -A 로 자르면 뒤따르는 키와 본문의
#       위키링크까지 딸려와 적지도 않은 쌍이 dup 으로 찍힌다(규칙 14 와 같은 이유)
blk() {  # 사용법: blk <파일> <술어>
  awk -v k="$2" '
    $0 ~ "^  " k ":"         { inblk=1; line=$0; sub("^  " k ":","",line); print line; next }
    inblk && /^---/          { inblk=0 }
    inblk && /^  [a-zA-Z]+:/ { inblk=0 }
    inblk                    { print }
  ' "$1" | grep -oE '\[\[[^]]+' | sed 's/\[\[//'
}
back=supportedBy; fwd=supports          # 비정본 키 / 정본 키
srcdir=objects/가설; dstdir=objects/근거
for f in $srcdir/*.md; do
  case "$f" in */사업체.md|*/제공물.md|*/고객군.md|*/가설.md) continue;; esac
  case "$f" in */근거.md|*/마일스톤.md|*/자금.md|*/제출문서.md) continue;; esac
  a=$(basename "$f" .md)
  blk "$f" "$back" | while IFS= read -r b; do
    g="$dstdir/$b.md"
    [ -f "$g" ] || continue
    blk "$g" "$fwd" | grep -qx "$a" \
      && echo "dup: $f <-> $g ($back/$fwd)"
  done
done

# 11-b 를 돌릴 목록 (비정본 -> 정본 / 비정본이 사는 폴더 -> 정본이 사는 폴더)
#   schema 요약표의 여덟 쌍이고, 소유 쌍은 키가 셋이고 판본 쌍은 폴더가 둘이라 줄이 열하나다
#   claimedIn    -> claims       가설 -> 제출문서
#   supportedBy  -> supports     가설 -> 근거
#   refutedBy    -> refutes      가설 -> 근거
#   testedBy     -> tests        가설 -> 마일스톤
#   offers       -> ownedBy      사업체   -> 제공물
#   pursues      -> ownedBy      사업체   -> 마일스톤
#   holds        -> ownedBy      사업체   -> 가설
#   servedBy     -> targets      고객군   -> 제공물
#   funds        -> fundedBy     자금   -> 마일스톤
#   supersededBy -> supersedes   제출문서  -> 제출문서
#   supersededBy -> supersedes   제공물  -> 제공물

# 12-a. 인스턴스에 broader 가 붙었는지
grep -rl '^broader:' objects/ \
  | grep -vE '/(사업체|제공물|고객군|가설|근거|마일스톤|자금|제출문서|venture-knowledge)\.md$'

# 12-b. ownedBy 대상이 사업체 가 아닌 것. WS 하나에 사업체 하나가 원칙이라
#       여기 나오는 값은 대개 사람 이름이거나 고객사 이름이고 그것이 위반의 전형이다.
#       여기도 blk 를 쓴다. grep -A5 로 자르면 바로 뒤 targets 와 assumes 의 링크가
#       전부 소유자로 잡혀 정상 노트가 통째로 위반으로 나온다
find 객체 -name '*.md' | while IFS= read -r f; do blk "$f" ownedBy; done \
  | sort -u > /tmp/owners.txt
ls objects/사업체/*.md | xargs -n1 basename | sed 's/\.md$//' \
  | grep -v '^사업체$' | sort -u > /tmp/사업체.txt
comm -23 /tmp/owners.txt /tmp/사업체.txt

# 13. falsifiable 이 빈 가설. 본문 섹션으로 쓰는 워크스페이스도 통과시킨다
for f in objects/가설/*.md objects/가설/*/*.md; do
  [ -f "$f" ] || continue
  case "$f" in */가설.md) continue;; esac
  grep -qE '^falsifiable: *[^ ]' "$f" || grep -q '^## 무엇이 관측되면' "$f" \
    || echo "no falsifier: $f"
done

# 15. collectedAt 또는 sampleSize 가 빈 관측
for f in objects/근거/*.md objects/근거/*/*.md; do
  [ -f "$f" ] || continue
  case "$f" in */근거.md) continue;; esac
  grep -qE '^collectedAt: *[0-9]' "$f" || echo "no collectedAt: $f"
  grep -qE '^sampleSize: *[^ ]' "$f" || echo "no sampleSize: $f"
done

# 18. 제출처가 있는데 제출일이나 판본이 없는 문서.
#     for f in $(grep -rl ...) 를 쓰지 않는다. 창업 자료에는 공백이 든 파일명이 흔하고
#     (사업계획서 최종.md) 단어 분리로 루프가 깨진다. PK 가 곧 파일명이라 위키링크
#     대상을 도는 루프도 같은 이유로 while read 로 받는다
grep -rlE '^submittedTo: *[^ ]' objects/제출문서/ | while IFS= read -r f; do
  grep -qE '^submittedAt: *[0-9]' "$f" || echo "no submittedAt: $f"
  grep -qE '^version: *[^ ]' "$f" || echo "no version: $f"
done

# 날짜 폴더와 Obsidian 잔재
find action-log -mindepth 1 -type d
find . -name '*.base'; grep -rl 'dataview' . --include='*.md'
```

## 규칙 14: 역방향 스캔

**이 검사만 다른 모양이다.** 정본이 근거 쪽 `supports` 라서 가설 노트 안에 근거의
흔적이 아예 없고, 가설 파일만 읽으면 `status: validated` 한 줄이 늘 멀쩡해 보인다.
그래서 **근거 폴더에서 가설 이름을 모아 validated 목록에서 뺀다.**

```sh
# 1) 근거 쪽에서 supports 로 가리킨 가설 이름을 모은다. grep -A 로 자르면 다음
#    키(refutes, ownedBy)의 링크까지 딸려와 집합이 커지고, 집합이 커지면 차집합이
#    작아져 위반을 놓친다. 블록 경계를 지키는 awk 를 쓴다
for f in objects/근거/*.md objects/근거/*/*.md; do
  [ -f "$f" ] || continue
  awk '
    /^  supports:/           { inblk=1; line=$0; sub(/^  supports:/,"",line); print line; next }
    inblk && /^---/          { inblk=0 }
    inblk && /^  [a-zA-Z]+:/ { inblk=0 }
    inblk                    { print }
  ' "$f"
done | grep -oE '\[\[[^]]+' | sed 's/\[\[//' | sort -u > /tmp/supported.txt

# 2) validated 가설 목록
grep -lE '^status: validated' objects/가설/*.md objects/가설/*/*.md 2>/dev/null \
  | xargs -n1 basename | sed 's/\.md$//' | sort -u > /tmp/validated.txt

# 3) 차집합. 왼쪽에만 남은 것이 근거 없는 validated 다
comm -23 /tmp/validated.txt /tmp/supported.txt
```

같은 방식으로 `invalidated` 도 본다. `supports` 를 `refutes` 로, `validated` 를
`invalidated` 로 바꾸면 된다.

여기서 나온 것은 셋 중 하나다. 근거 노트를 안 만들었으면 만든다. 네 줄이면
성립한다. 있는데 `supports` 를 안 걸었으면 링크만 건다. 근거 없이 상태를 올렸으면
`unvalidated` 로 되돌린다. **셋째가 가장 비싼 거짓말이다.**

## 규율 검사 (16, 17)

**이 둘은 구조 검사가 아니다.** 명령이 내는 것은 후보 목록이고 판정은 사람이 한다.
이 프리셋이 실패하는 방식은 **출처 없는 숫자와 반증 후에도 살아남는 전제**이고, 둘 다
문법적으로는 완벽한 노트의 모습을 하고 있다.

### 16. 숫자 출처

```sh
# 정량 표현 후보. 본문에 숫자가 단위와 함께 나오는 자리를 전부 뽑는다
grep -rnE '[0-9][0-9,.]*(조|억|천만|만원|원|퍼센트|%|배|건|명|개사|곳)' \
  objects/ object-views/ object-sets/ --include='*.md'

# 그 파일의 출처 칸이 비었는지 본다. sources 배열, 본문 url, 근거 의 source 중
# 하나라도 있으면 통과다
grep -rlE '[0-9][0-9,.]*(조|억|천만|만원|원|퍼센트|%|배|건|명|개사|곳)' \
  objects/ --include='*.md' | while IFS= read -r f; do
  case "$f" in
    */사업체.md|*/제공물.md|*/고객군.md|*/가설.md) continue;;
    */근거.md|*/마일스톤.md|*/자금.md|*/제출문서.md) continue;;
  esac
  grep -qE '^sources: *\[[^]]' "$f" && continue
  grep -qE '^ *- *https?://' "$f" && continue
  grep -qE '^source: *[^ ]' "$f" && continue
  echo "unsourced number: $f"
done
```

후보에는 출처가 필요 없는 것이 섞인다. 근거 의 `sampleSize` 와 자금 의 `amount`
다. 지우고 나머지를 본다. 판정 기준은 **어디서 가져왔는지 답할 수 있는가** 하나다.

- 위반: 고객군 의 `size` 에 출처 없이 있는 "국내 시장 규모 1.2조원". 못 적겠으면
  숫자를 비우고 가설 로 올린다. 추정은 주장이다.
- 위반: 제공물 의 `valueProp` 에 있는 "도입 기간을 2주로 줄인다". 측정된 값이면
  근거 가 있어야 하고, 목표값이면 마일스톤 의 `definitionOfDone` 이다.
- 위반 아님: 근거 의 `finding` 에 있는 "다섯 곳 중 네 곳". 이 노트 자체가 관측
  기록이고 `sampleSize` 와 `collectedAt` 이 출처 역할을 한다.

**가장 자주 걸리는 자리는 고객군 의 `size` 와 제출문서 에서 옮겨 적은 본문이다.**
제출용 문장은 확신의 정도를 지운 채로 온다.

### 17. 반증된 가설 위에 산 것

```sh
# 1) 반증된 가설 목록
grep -lE '^status: invalidated' objects/가설/*.md objects/가설/*/*.md 2>/dev/null \
  | xargs -n1 basename | sed 's/\.md$//' | sort -u > /tmp/invalidated.txt

# 2) assumes 로 그것을 가리키면서 아직 활성 상태인 제공물 / 고객군 / 자금.
#    죽은 상태: 제공물=retired, 고객군=parked, 자금=rejected 또는 closed
for f in objects/제공물/*.md objects/고객군/*.md objects/자금/*.md \
         objects/제공물/*/*.md objects/고객군/*/*.md objects/자금/*/*.md; do
  [ -f "$f" ] || continue
  case "$f" in */제공물.md|*/고객군.md|*/자금.md) continue;; esac
  grep -qE '^status: (retired|parked|rejected|closed)' "$f" && continue
  awk '
      /^  assumes:/            { inblk=1; line=$0; sub(/^  assumes:/,"",line); print line; next }
      inblk && /^---/          { inblk=0 }
      inblk && /^  [a-zA-Z]+:/ { inblk=0 }
      inblk                    { print }
    ' "$f" | grep -oE '\[\[[^]]+' | sed 's/\[\[//' | while IFS= read -r h; do
    grep -qx "$h" /tmp/invalidated.txt && echo "live on invalidated [$h]: $f"
  done
done
```

`assumes` 블록을 awk 로 자르는 이유는 규칙 14 와 같다. 파일 전체에서 가설 이름을 찾으면
본문에 지나가듯 언급된 위키링크까지 걸려 후보가 잡음으로 덮인다. 걸린 것은 셋 중 하나다.

1. 피봇을 하다 말았다. **이 경우가 가장 많다.** [[창업]] 의 피봇 절차 둘째 단계를
   안 한 것이고, 그 상태로 신청서를 쓰면 옛 타깃이 그대로 들어간다.
2. 가설은 반증됐는데 제품은 다른 이유로 유효하다. `assumes` 를 끊고 지금 딛고 선
   전제를 새 가설로 적는다. 끊기만 하면 전제 없는 제품이 된다.
3. 상태 enum 만 안 바뀌었다. 바꾸면 끝난다.

## 조회 레시피 (Dataview 대체)

읽는 시점에 실행해 결과를 만든다. 아래 여럿이 같은 awk 를 쓰므로 함수로 뺀다.

```sh
lnk() {  # 사용법: lnk <파일> <술어>
  awk -v k="$2" '
    $0 ~ "^  " k ":"         { inblk=1; line=$0; sub("^  " k ":","",line); print line; next }
    inblk && /^---/          { inblk=0 }
    inblk && /^  [a-zA-Z]+:/ { inblk=0 }
    inblk                    { print }
  ' "$1" | grep -oE '\[\[[^]]+' | sed 's/\[\[//'
}

# (a) 지금 근거 없이 주장하고 있는 것. unvalidated 인데 어느 문서의 claims 에 걸려
#     있는 가설이고, 심사장에서 근거를 물으면 답할 것이 없는 자리다
for f in objects/제출문서/*.md objects/제출문서/*/*.md; do
  [ -f "$f" ] || continue; lnk "$f" claims
done | sort -u > /tmp/claimed.txt
grep -lE '^status: unvalidated' objects/가설/*.md objects/가설/*/*.md 2>/dev/null \
  | xargs -n1 basename | sed 's/\.md$//' | sort -u > /tmp/unvalidated.txt
comm -12 /tmp/unvalidated.txt /tmp/claimed.txt

# (b) 이 공고에 내려면 아직 없는 서류. 자금 의 requires 중 대응 제출문서 가 없는 것
F=objects/자금/2026-예비창업패키지.md
lnk "$F" requires | while IFS= read -r a; do
  [ -f "objects/제출문서/$a.md" ] || [ -f "objects/제출문서/$a/$a.md" ] \
    || echo "missing 제출문서: $a"
done

# (c) 제출 전 점검. 이 문서가 주장하는 것 중 아직 validated 가 아닌 것.
#     제출 버튼을 누르기 전에 돌리는 조회이고 이 워크스페이스를 쓰는 가장 큰 이유다
A=objects/제출문서/사업계획서.md
lnk "$A" claims | while IFS= read -r h; do
  g=$(ls "objects/가설/$h.md" "objects/가설/$h/$h.md" 2>/dev/null | head -1)
  if [ -z "$g" ]; then echo "dangling claim: $h"; continue; fi
  grep -qE '^status: validated' "$g" \
    || echo "unbacked: $h  [$(grep -m1 '^status:' "$g" | tr -d ' ')]"
done

# (d) 최신판이 무엇인가. 다른 문서가 supersedes 로 가리키지 않고 status 도
#     superseded 가 아닌 제출문서
for f in objects/제출문서/*.md objects/제출문서/*/*.md; do
  [ -f "$f" ] || continue; lnk "$f" supersedes
done | sort -u > /tmp/old-제출문서.txt
for f in objects/제출문서/*.md objects/제출문서/*/*.md; do
  [ -f "$f" ] || continue
  case "$f" in */제출문서.md) continue;; esac
  grep -qE '^status: superseded' "$f" && continue
  a=$(basename "$f" .md)
  if grep -qx "$a" /tmp/old-제출문서.txt; then echo "stale head: $f"; continue; fi
  echo "current: $f  [$(grep -m1 '^version:' "$f" | tr -d ' ')]"
done   # stale head 는 대체됐는데 status 를 안 바꾼 문서다. status 만 바꾸면 된다

# (e) 이 고객군에 대해 실제로 아는 것. aboutSegment 로 걸린 근거 와 그 규모
S=안경원
for f in objects/근거/*.md objects/근거/*/*.md; do
  [ -f "$f" ] || continue
  lnk "$f" aboutSegment | grep -qx "$S" || continue
  echo "$(grep -m1 '^collectedAt:' "$f" | tr -d ' ')  $(grep -m1 '^kind:' "$f" | tr -d ' ')  $(grep -m1 '^sampleSize:' "$f")  $f"
done | sort
#     규모 합계. 인터뷰 건수와 매출 건수가 섞이면 합이 뜻을 잃으니 위 목록을 먼저 본다
for f in objects/근거/*.md objects/근거/*/*.md; do
  [ -f "$f" ] || continue
  lnk "$f" aboutSegment | grep -qx "$S" || continue
  grep -m1 '^sampleSize:' "$f"
done | grep -oE '[0-9]+' | paste -sd+ - | bc

# (f) 반년째 안 움직인 가설. statedAt 이 오래됐고 unvalidated 이고 어느 마일스톤도
#     tests 로 걸지 않은 것. 날짜 비교에 [[ ]] 를 쓰므로 bash 로 돌린다
CUT=2026-03-16
for f in objects/마일스톤/*.md objects/마일스톤/*/*.md; do
  [ -f "$f" ] || continue; lnk "$f" tests
done | sort -u > /tmp/tested.txt
for f in objects/가설/*.md objects/가설/*/*.md; do
  [ -f "$f" ] || continue
  case "$f" in */가설.md) continue;; esac
  grep -qE '^status: unvalidated' "$f" || continue
  d=$(grep -m1 '^statedAt:' "$f" | sed 's/^statedAt: *//' | tr -d ' ')
  if [ -z "$d" ]; then echo "no statedAt: $f"; continue; fi
  [[ "$d" < "$CUT" ]] || continue
  h=$(basename "$f" .md)
  grep -qx "$h" /tmp/tested.txt && continue
  echo "stale 가설: $f  ($d)"
done
```

(f) 에서 나온 것을 전부 검증하려 들지 않는다. 지금도 중요한데 미룬 것은 마일스톤 을
만들어 `tests` 를 건다. 더는 묻지 않게 된 것은 `retired` 로 닫는다. 반증 조건이 없어
검증할 방법이 없는 것은 규칙 13 위반이고, 가설이 아니라 구호라서 지운다.

## lint 를 언제 돌리나

셋이다. 앞의 둘이 이 프리셋의 본체이고 마지막 하나가 team-ops 와 같은 주기다.

**1. 문서를 제출하기 전. 가장 중요하다.** 조회 레시피 (c) 를 그 문서에 대고 돌린다.
신청서와 IR 덱은 한 번 나가면 회수가 안 되고, 거기 들어간 미검증 주장은 대면평가에서
근거를 요구받는다. (c) 가 아무것도 안 내면 그대로 낸다. 무언가 나오면 근거를 찾아
근거 를 만들거나 그 문장을 빼거나 수위를 낮춘다. **상태를 올려서 통과시키지
않는다.** 그것이 규칙 14 가 잡으려는 바로 그 동작이다.

**2. 가설 상태를 바꾼 직후. 규칙 17 이다.** `invalidated` 를 찍는 순간이 피봇의 첫
단계이고, 나머지 두 단계를 그 자리에서 마치지 않으면 영영 안 한다. 저장한 다음 규칙
17 명령 하나만 돌린다. 30초면 끝나고, 여기서 걸리는 제공물 과 자금 이 반년 뒤
신청서에 옛 타깃이 남는 사고의 원인이다. `validated` 로 올릴 때는 규칙 14 를 같은
자리에서 돌린다. 통과하지 못하면 근거 없이 올린 것이다.

**3. 분기에 한 번 전체.** 규칙 7~18 을 순서대로 돌리고 규율 검사 16 도 함께 본다.
이 세 번째는 위반을 찾는 작업이 아니라 **늘고 있는지 보는** 작업이다. 지난 분기보다
출처 없는 숫자가 늘었으면 문서를 급하게 썼다는 뜻이고, 반증된 가설 위에 산 것이
늘었으면 피봇을 마무리 안 하는 습관이 생긴 것이다. 숫자보다 그 방향이 신호다.

지원사업 시즌에는 1번이 주 단위로 돌아간다. 그때 3번을 같이 돌리지 않는다. 마감 직전의
전체 lint 는 고칠 시간이 없는 목록만 남긴다. 시즌이 끝난 뒤에 돌린다.
